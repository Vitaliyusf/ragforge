# CI-02 — Harden GitHub Actions and align developer Python version

**Branch:** `chore/ci-actions-hardening`

## Goal
Make GitHub Actions clearer, safer, and easier to diagnose while keeping CI as the repository-wide validation layer.

## Problem
The current CI has several avoidable issues:
- Ruff and mypy run sequentially in one job, so a Ruff failure prevents mypy from running.
- Official GitHub actions emit Node-runtime deprecation warnings.
- The repo CI uses Python 3.11 while local agent environments can drift to another version.
- Job permissions/timeouts are implicit.
- Agent-local validation should stay focused; CI should remain broad.

## Primary scope
- `.github/workflows/ci.yml`
- root `.python-version`
- CI-related documentation only if required

## Required behavior

### Python source of truth
- Add root `.python-version` with `3.11`.
- Make CI consume the repository Python version from this file where practical.
- Preserve Python 3.11 as the runtime/test target.

### Split lint and type checking
Replace the combined lint/type-check job with independent jobs:
- Ruff repo-wide lint.
- Strict mypy using the repository's existing authoritative scope:
  - `backend/shared`
  - `backend/gateway/app`
  - `--config-file mypy.ini`

A Ruff failure must not prevent the mypy job from running.

### Official GitHub actions
- Inspect current supported stable major versions of:
  - `actions/checkout`
  - `actions/setup-python`
  - `actions/setup-node`
- Upgrade from deprecated-runtime versions to currently supported stable majors.
- Do not change the application's Node test target merely because the action runtime changes.
- Keep frontend Node version aligned with the project's current supported runtime unless a separate task changes it.

### CI safety / operability
- Add explicit least-privilege workflow permissions:
  - `contents: read`
- Add reasonable `timeout-minutes` to jobs.
- Preserve existing workflow concurrency/cancel-in-progress behavior.
- Preserve the backend service matrix:
  - embedding
  - files
  - gateway
  - llm_agent
  - memory
  - rag
  - vector_db
- Preserve shared tests, frontend tests, repo guardrails, repo-wide Ruff, and strict mypy coverage.

### Do not weaken CI
Do NOT add path-based skipping of backend/frontend suites in this task.
CI remains the broad safety net while local agents run focused checks.

## Acceptance
- Ruff and mypy are separate jobs and can report independently.
- `.python-version` exists and declares Python 3.11.
- CI uses supported official GitHub action majors without Node-runtime deprecation warnings from obsolete action runtimes.
- Workflow has explicit read-only contents permission.
- Jobs have bounded timeouts.
- Backend matrix/shared/frontend/guardrails remain present.
- Workflow YAML is valid.
- No test/lint/type-check coverage is reduced.

## Validation
- Validate YAML syntax / workflow structure.
- Review the final workflow diff carefully.
- If feasible, trigger/inspect a PR CI run and verify all jobs appear independently.
- Do not run the full repository test suite locally just because the workflow file changed; CI is the authoritative full run.
